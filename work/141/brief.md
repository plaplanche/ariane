# Product brief: End an agent session that shows no activity for a set time, with a clear stop reason (C5)

- Source: issue #141 (https://github.com/plaplanche/ariane/issues/141)

## Issue

## Context

Each agent session has a total time limit (C5). Within it, nothing notices a session that has stopped making progress. In the benchmark on a reference project, an implementer spent about fifteen minutes in a shell loop it had written that could never end (`until [ -n "$(grep -l . /dev/null)" ]; do sleep 5; done`) until the shell tool's own command timeout ended it; the session's budget and time went to waiting. Ariane reads every session's event stream line by line, so it can see when no event has arrived for a long time. Spec: C5 (time limit, stop reason classified by Ariane, clear status).

## Current state

- `src/ariane/process.py:102-121`: `stream` passes each standard-output line to `on_line` and kills the process tree when `on_line` returns True or at `timeout_s`; `_execute` waits with `proc.wait(timeout=timeout_s)` (`process.py:163-166`). There is no limit on the time between two lines.
- `src/ariane/claude_code.py:87-115` and `src/ariane/opencode.py:101-128` map a kill at `timeout_s` to `StopReason.TIMEOUT`, "killed after <s> s (time limit)".
- `src/ariane/config.py:37-44`: `AgentConfig` has `timeout_minutes` only.

## Decided spec

- `process.stream` gains `idle_timeout_s: float | None`: when no standard-output line has arrived for that long, the whole process tree is killed and `Completed.idle` is set (a new field, False by default).
- New optional key `agents.<role>.idle_minutes` (positive number), for both roles and both runtimes. A value given must be below `timeout_minutes`, or it is refused naming the key. When the key is absent the idle limit is 10 minutes, or none when `timeout_minutes` is 10 or less (the total limit already applies).
- Both runtimes pass it through `Session.idle_timeout_s` and map an idle kill to `StopReason.TIMEOUT` with the summary "no activity for <m> min (idle limit); last event: <the last line's event type and tool name, when it was a tool call>". The stop reasons of C5 stay the five of the spec.
- The journal's stop entry and the stop line show that summary; the work is kept on the branch as for any timeout.
- The 10-minute default is the simplest that leaves room for a long test run, since a shell command in a Claude Code session runs at most 10 minutes unless its settings raise that limit (to be confirmed by the implementer on the installed version, and said in the ADR); a new ADR (next free number) records the default, why activity is measured on the event stream only (not on file changes), and that the owner may change it.

## Release note

Added: an agent session with no activity for `idle_minutes` (10 by default) is stopped as a timeout, saying so.
