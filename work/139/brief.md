# Product brief: opencode reviewer: a token cap that fits a normal review, and a stop that says which cap to raise (C5, C10)

## Context

opencode does not cap its own cost, so Ariane requires `max_tokens` for an opencode reviewer and stops the session when the tokens it counts reach it (C5, ADR 0029). Those tokens include cache reads, which opencode reports again at every step, so the count grows much faster than the size of the context. In the benchmark on a reference project, an opencode reviewer (GPT-5) stopped at the 400,000-token cap of the example configuration on a normal ticket; the same review finished under a 1,500,000 cap. The stop said "the reviewer session stopped: budget" without naming the cap or the key to change. Spec: C5 (budget, stop reason, clear status), C10.

## Current state

- `docs/ariane.opencode-reviewer.example.toml:30`: `max_tokens = 400000`, the only value users copy; `src/ariane/config.py:299-303` requires the key for opencode and has no default.
- `src/ariane/opencode.py:158-160`: the counted total is input + cache read + cache write + output, summed over every `step_finish`; the cap is checked at `opencode.py:206-208`.
- `src/ariane/review_session.py:126-131`: the `ticket.review.stopped` entry gives cost and tokens but not `result.cap`, unlike the implementer's entry (`src/ariane/flow.py:251-257`, "Cap reached: ...").
- `src/ariane/review_session.py:134-139`: a reviewer stopped by a cap raises `ReviewFailed("the reviewer session stopped: budget", "read work/<n>/journal.md; Ariane pushed nothing")`.

## Decided spec

- `docs/ariane.opencode-reviewer.example.toml`: `max_tokens = 1500000`, and its comment says that the count includes cache reads, re-reported at each step, so a normal review counts over a million tokens.
- `ticket.review.stopped` starts with "Cap reached: <cap>." when the session stopped at a cap, as the implementer's entry does.
- A reviewer session stopped at a cap gives the reason "the reviewer session stopped at <cap>" and the next action "raise `agents.reviewer.max_tokens` (token cap) or `agents.reviewer.max_budget_usd` (cost cap) in ariane.toml; the work is kept on branch ariane/<n>", naming the key of the cap that applied. Other stop reasons keep today's text.
- The cap stays a hard stop (C5: Ariane stops at the cap); a soft budget is not introduced. What the count includes is unchanged (C5: tokens as reported, cache included).
- ADR 0029 gets a dated amendment with the new example value and why.
