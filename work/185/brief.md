# Product brief: Risk tier per round: ARIANE_RISK_TIER and ARIANE_FULL_SUITE (C9)

## Context

Selective checks (#184, `checks[].paths`) skip checks that a ticket cannot affect. The owner also wants the amount of testing to follow the ticket's complexity: a small, local change can run only the related tests, a large one or one touching critical code runs the full suite. This ticket gives each round a risk tier computed from the diff and the configuration, and passes it to the checks so a project can choose between a related-tests run and a full run. Spec: C9; depends on #184. The same tier is meant to size the reviewer (#137).

## Current state

- After #184: a check is selected by `paths` / `always`, and gets `ARIANE_CHANGED_FILES`.
- Nothing measures the size or the reach of a ticket's diff before the replay.

## Decided spec

- **Risk tier.** For each round, Ariane computes a tier, `low` or `high`, from the diff from the base commit:
  - `high` when any of: more than `max_changed_lines` lines added and removed (default 300); more than `max_modules` top-level folders, or packages, touched (default 3; a "module" is the first path segment under each root the project lists, default the repository root); a changed file matches `critical_paths`; the diff touches `ariane.toml` or `check_all_paths`; a previous round of the same ticket failed a check;
  - `low` otherwise.
  Configuration in a new optional table `[checks_policy]`: `max_changed_lines`, `max_modules`, `module_roots` (globs of the folders whose children count as modules, for example `["src/*/"]`), `critical_paths` (globs). Without the table, the tier is always `high` (no behaviour change).
- **Effect on the checks.** Every check gets `ARIANE_RISK_TIER=low|high`. A check may declare `full_when = "high"` (the default) or `"always"`: Ariane sets `ARIANE_FULL_SUITE=1` for that check when the tier is `high` or when `full_when = "always"`, and `0` otherwise; the project's command decides what a related-tests run is (for example a script that runs the tests related to `ARIANE_CHANGED_FILES` when `ARIANE_FULL_SUITE=0`). Selection by `paths` still applies first.
- **Records.** `checks.md` starts with the tier and the reasons (for example "high: 412 changed lines; touches `critical_paths` `src/auth/**`"); the journal logs `ticket.checks.risk_tier` with the tier and the reasons; the pull request body and the reviewer's prompt state it.
- **Reviewer sizing.** The tier is exposed to the reviewer sizing of #137 if it exists when this ticket is built (`high` keeps the full review); otherwise the ADR records it as the intended input.
- ADR amendment to the selective checks ADR: the tier, its default thresholds, why it is computed from the diff and not asked of the implementer, why a failed round forces `high`.

## Release note

Added: each round has a risk tier (`low` or `high`) computed from the diff and `[checks_policy]`; checks receive `ARIANE_RISK_TIER` and `ARIANE_FULL_SUITE` to run only related tests on low-risk changes.

## Acceptance criteria

- Tests named `test_c9_risk_tier_*` show:
  - without `[checks_policy]`, the tier is `high` and every check gets `ARIANE_FULL_SUITE=1`;
  - a small diff in one module is `low`; each of the `high` reasons (line count, module count, `critical_paths`, configuration file, failed previous round) makes it `high`, and the reasons are recorded;
  - `full_when = "always"` keeps `ARIANE_FULL_SUITE=1` on a `low` round;
  - the schema refuses unknown keys, a non-positive threshold and a non-string glob in `[checks_policy]`.
