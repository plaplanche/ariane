# Product brief: Dependency cache for the replay: folders stored by lock-file content, copied instead of reinstalled (C9)

## Context

Every replay builds each check's tree from scratch: a fresh working tree, then `project.setup` (or the check's own `setup`). For a project with Node dependencies that means `npm ci` in every tree of every round: on a ten-ticket benchmark project the replay trees held several gigabytes of identical `node_modules`, and the installs cost minutes per round. The clean tree is the point of C9 (nothing the agent left can make a check pass), but the dependencies installed from the same lock file are the same every time. Spec: C9 (checks replayed in clean trees).

## Current state

- `config`: `project.setup` and `checks[].setup` are commands run in each fresh tree before its check.
- `replay.py` and `checks.py` create one tree per check and per round, and remove them afterwards.
- Nothing is kept between trees, rounds or tickets.

## Decided spec

- **Declared caches.** A new optional table list `[[project.cache]]`, each with `path` (a folder relative to the tree, such as `worker/node_modules` or `.venv`), `key` (files whose content identifies it, such as `["worker/package-lock.json"]`), and `setup` (the command that builds that folder alone, such as `["npm", "ci", "--prefix", "worker"]`).
- **Content-addressed store.** The key is the SHA-256 of the key files' contents and of the `setup` command. On a miss, Ariane runs that `setup` in the fresh tree, then copies the built folder into `<repo>.ariane/cache/<key>/` (made read-only). On a hit, it copies the stored folder into the fresh tree instead of running that `setup`. The copy uses copy-on-write clones where the file system supports them, otherwise a plain copy; never hard links (a tool writing into the folder must not change the store). `project.setup` then runs as today, for whatever the caches do not cover.
- **Safety.** A store entry is used only when it was written completely (written to a temporary name, renamed when done); an entry Ariane cannot read is rebuilt, never trusted partially. The agent's tree is never used to fill the store: only Ariane's own replay trees, built from the commit. The journal says, per check, which caches hit and which were built.
- **Limits.** `ariane` keeps at most the 5 most recent entries per `path` and removes older ones at the start of a ticket; a setting can change it.
- ADR (next free number): why copies and not links, the key, and why only replay trees fill the store.
