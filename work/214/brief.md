# Product brief: Fewer git processes per run: measure by phase, then cut the three costliest, same guarantees (C9, C11)

- Source: issue #214 (https://github.com/plaplanche/ariane/issues/214)

## Issue

Prefilled from the issue title and body (never its comments).

## Context

#206 (ADR 0049) measured where the test suite spends its time on Windows: the 30 slowest tests (22 to 49 s each on `windows-latest`, about 7 times their Linux time) are all whole Ariane runs driven by a fake runtime: `flow.start` through setup, replay in fresh working trees, review, fix rounds and delivery to a bare remote. Their cost is Ariane's own git and process work during a run (100 to 190 git processes per test on Linux), not the tests' set-up, which #206 already cut. The same work runs in real tickets, where it is small next to the agents' time but still adds seconds per round, most on Windows. Spec: C9 (checks), C11 (push guard); CLAUDE.md rule 6.

## Current state

- A run verifies git after each phase ("Verified after the agent session", "after the checks", several times per round): `git.config_snapshot` and the remote refs (`git ls-remote`) each start git processes.
- Each check is replayed in its own fresh working tree (`git worktree add`, then removal), per round.
- The journal and records are committed several times per run; delivery pushes to the remote and lists it again.
- Nothing measures how many processes each phase starts.

## Decided spec

- **Measure first.** A test helper counts the processes Ariane starts (through `process.run`), by phase (setup, session, guard verification, replay, review, record commits, delivery), for three whole-run tests: a go on the first round, three no-go rounds to a draft, and a restart. The ADR records the counts and times per phase on Linux, and on Windows from the pull request's CI (`--durations`).
- **Then cut the three costliest phases, without weakening any guarantee:** for example one `git for-each-ref` and a direct read of the configuration files instead of several processes per verification; one listing of the remote per phase instead of one per check; batching the record commits of a phase. Each change keeps what the guard compares (ADR 0017) and the clean-tree replay (C9) exactly as they are; a test per change shows that the guard still stops on the same tampering (a changed hook, config key, ref or remote branch) as before.
- **Tests keep testing the same behaviour.** No whole-run test is removed, skipped or made to assert less; a test may share a built bare remote within a worker (as `project_template` does) when it only reads it.
- Target: the sum of the 30 slowest Windows tests drops by at least 40 % against the figures in ADR 0049, measured on the pull request's own CI.
- ADR (next free number): the counts per phase before and after, what each cut keeps of the guard and the replay, and the Windows figures.

## Release note

Changed: a run starts fewer git processes per round (guard verification, remote listing, record commits), with the same guarantees; the whole-run tests and real tickets get faster, most on Windows.
