# Product brief: Two tickets at once on one repository: the push guard tolerates another Ariane run's own branch, and nothing else (C11)

## Context

Running two tickets at once on the same repository (two `ariane start`, each in its own worktree) fails today: while ticket #141 ran, ticket #136 started and created its branch, and #141 was stopped with "the agent session changed git configuration, hooks or local branches" because of the entry `branch.ariane/136.remote=origin` written by the other Ariane run, not by #141's agent. The push guard is right to stop on any change an agent makes to git itself, but it cannot tell an agent's change from another Ariane run's own bookkeeping. Running tickets in parallel is the first step of the orchestration the benchmark points to (`docs/benchmark.md`, #130, #152). Spec: C11 (delivery and push guard), C23; ADR 0017 (push guard revision).

## Current state

- `src/ariane/flow.py:179`: `guard = git.config_snapshot(self.worktree, ignore_ref=self.branch)` before the agent session; `flow.py:182` compares after it and stops the ticket on any difference.
- `src/ariane/git.py:187-212` `config_snapshot`: digests of the shared `config`, `config.worktree`, the `hooks/` and `info/` folders, every configuration scope, and the local branches and tags except the ticket's own branch.
- Nothing records which tickets Ariane is running on the repository, so the guard has no way to know that `ariane/136` and its config section belong to another Ariane run.
- The stop message says "nobody runs git commands in the repository or pushes to it while a ticket runs": parallel tickets are not supported today.

## Decided spec

- **Run registry.** When a ticket starts, Ariane records it in `<repo>.ariane/runs/<n>` (the ticket number, the branch, the process id, the start time) and removes the entry when the run ends, however it ends; an entry whose process no longer exists is ignored and cleaned. If #140's per-ticket lock exists when this ticket is built, the registry is that lock's file; otherwise this ticket writes it and #140 reuses it.
- **What the guard tolerates, and nothing more.** A difference between the two snapshots is ignored only when all of it is, for a ticket `m` registered as running (or that was running at any time during the session):
  - the local branch `ariane/<m>` created, moved or deleted;
  - in the shared `config`, the keys `branch.ariane/<m>.remote` (value `origin`) and `branch.ariane/<m>.merge` (value `refs/heads/ariane/<m>`) added or removed, and no other key of that section.
  Any other change (another key in that section such as `pushRemote`, a hook, another branch, another scope) still stops the ticket, as today. To compare the shared config by key instead of by digest, the snapshot of that one file keeps its parsed keys (`git config --file <path> --list`) next to the digest.
- **Message.** The stop message no longer says that nobody may run Ariane in parallel; it names the changes that are not another run's own.
- ADR 0017 amendment: why other Ariane runs' branch bookkeeping is tolerated, and why only those exact keys.

## Release note

Changed: two tickets can run at once on one repository; the push guard ignores another Ariane run's own branch and its two branch keys, and still stops on anything else.
