# Product brief: Review in proportion: accepted residuals and ticket scope for the reviewer, sensitive paths labelled for the owner (C10, C26)

- Source: issue #210 (https://github.com/plaplanche/ariane/issues/210)

## Context

The reviewer (C10) judges a change against the ticket and the definition of done, but nothing tells it what the owner already decided, and nothing marks a change that needs the owner's own eyes. On recent tickets the reviewer kept raising, as blocking, cases the owner had already accepted as residuals in an ADR (until the operating-system sandbox), and edge cases outside the ticket's scope; each one cost a fix round or a hand takeover. In the other direction, a change to the push guard or to a workflow file gets the same review as a change to a README. Spec: C10 (review), C26 (definition of done item by item).

## Current state

- `review.prompt` gives the issue, its Out of scope section, the diff, the checks, the definition of done and the project instructions.
- ADRs record accepted residuals as prose ("Residuals, accepted by the owner until ..."), with no marker the reviewer is told to read.
- The small review (ADR 0046) narrows a small change; there is no notion of a sensitive path.

## Decided spec

- **Accepted residuals are data for the reviewer.** An ADR records an accepted residual as a line starting with `- **Accepted residual.**`. Ariane collects these lines from `docs/adr/` at the base commit and gives them to the reviewer, in an untrusted-data block, with the rule: a finding that is one of these residuals is `minor`, with "accepted residual (ADR NNNN)" in its title. The existing residual paragraphs of ADRs 0017, 0031 and 0047 get the marker.
- **Proportion.** The reviewer's rules add: a case the ticket and the specification do not ask for, and that no acceptance criterion covers, is `minor` unless it loses data, breaks a security property or makes a check pass wrongly; then it stays blocking and says which.
- **Sensitive paths.** A new optional setting `[review] sensitive_paths` (globs). When the change touches one, the reviewer is told so, the pull request gets the label `owner-review` and its body says, above the review, which sensitive paths changed. Ariane's own `ariane.toml` lists the push guard, the runs registry, redaction, process handling and `.github/**`.
- ADR (next free number): the marker, the proportion rule and its exceptions, and the label.
