# Product brief: Issue gate: wait briefly for the label event GitHub has not listed yet, instead of refusing at once (C21)

- Source: issue #138 (https://github.com/plaplanche/ariane/issues/138)

## Issue

Prefilled from the issue title and body (never its comments).

## Context

`ariane start` only runs an issue labelled by a writer and unchanged since (ADR 0032). It reads who added the label from the issue's events. Right after an issue is created with the label (or the label is added), GitHub's events endpoint does not list the `labeled` event yet for a few seconds, while the issue already shows the label. In the benchmark, `ariane start` run right after creating its issues was refused with "no event shows who added the label", and had to be run again by hand. Spec: C21 (the issue gate), C23 (one line, a next action).

## Current state

- `src/ariane/github.py:65-113`: `_check_trusted` reads the labels from the issue, then the events once (`github.py:79-89`). When the label is on the issue but no `labeled` event for it is listed, it raises `IssueRefused` "no event shows who added the label" (`github.py:94-97`); when the issue's `updated_at` is later than the last listed `labeled` event, it refuses "changed after the label" (`github.py:109-113`), which a re-added label not listed yet also triggers.
- `src/ariane/flow.py:55-58`: a refusal ends `start` with exit 2 before anything is created.
- Tests: `tests/test_c21_issue_gate.py`, with a fake GitHub server.

## Decided spec

- When the label is on the issue and the events give one of those two refusals, Ariane reads the events again, up to 4 more times, waiting 1, 2, 4 then 8 seconds before each (15 seconds in all), and decides on the last read. The issue itself is not read again (its labels and `updated_at` stay those of the first read).
- Every other outcome is decided on the first read, as today: label absent, labeller who cannot write, an API error.
- A technical log `github.label_event_retry` (info) says which read is retried and why; the refusal text is unchanged.
- The wait is injectable (`GitHubTracker(..., sleep=time.sleep)`) so tests do not wait.
- No ADR: ADR 0032 gets a one-line amendment ("the events are read again for up to 15 s when they lag behind the issue").

## Release note

Fixed: `ariane start` right after labelling an issue no longer fails because GitHub has not listed the label event yet.
