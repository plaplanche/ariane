# Product brief: Give each Ariane run a machine-wide slot number, ARIANE_SLOT, so projects can keep their local resources apart (C11, C22)

## Context

A project's checks and agents often start local services on fixed ports. In the benchmark on a reference project, two Ariane runs on one machine (two attempts on two repositories) both started the project's local stack on the same port, and one replay failed for that reason only. Ariane does not know a project's ports, but it can give every run a small number that no other Ariane run on the machine holds at the same time, and tell the project's code; the project then derives its ports, or anything else it must not share, from it. The non-functional requirements say that several projects on one machine never share state; C11 that two tickets never share a working tree; C22 that Ariane tells each session its role in an environment variable, so the project's instructions can adapt. Running one Ariane instance per machine (C13) is frozen.

## Current state

- Nothing in `src/ariane/` lets two runs tell each other apart: the only per-run value given to children is `ARIANE_ROLE` (`src/ariane/claude_code.py:94`, `src/ariane/opencode.py:89`), and only to agents.
- The setup and the checks get `untrusted_environment` (`src/ariane/context.py:110-145`), with nothing per run.
- There is no lock of any kind (no `lock` in `src/ariane/`).

## Decided spec

- **Slot.** At its start, before the setup, `ariane start` (shadow included) and `ariane verify` take the lowest slot `k` from 0 to 15 whose file `~/.ariane/slots/<k>.lock` they can lock with an operating-system file lock (`fcntl.flock` on POSIX, `msvcrt.locking` on Windows; the same helper as the ticket lock if that ticket is done first), and hold it to their exit; the system releases it if the process dies. All 16 held: refuse before any branch with "16 Ariane runs already hold a slot on this machine. Next: wait for one to end."
- **Given to the project.** `ARIANE_SLOT=<k>` is set in the environment of the setup, every check, every agent session and the commit hooks, after Ariane's own `ARIANE_*` variables are withheld.
- **Records.** The journal's `ticket.started` entry (and `verify`'s record) names the slot.
- **Documentation.** The README explains the variable with one example: a check script that picks its port as a base port plus `ARIANE_SLOT`, in PowerShell and bash.
- A new ADR (next free number) records the slot, the limit of 16, the place of the lock files, and the rejected alternative: a per-run lock on resources declared in `ariane.toml`, which would serialise runs and not help an agent that starts the stack itself.
