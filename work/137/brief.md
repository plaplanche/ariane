# Product brief: Size the review to the change: optional reviewer settings and a narrower prompt for small diffs (C10, C5, C19)

## Context

The review is the largest cost of a ticket and does not depend on the ticket's size. In the benchmark on a reference project, the review cost $0.78 of the $0.88 of a small ticket, and the reviewer was 61% of the total cost over a lot of ten tickets. C10 requires the review by a different model, whatever the size; it does not require the same depth for a ten-line change as for a new module. C3 (risk-based depth, slice 5) will choose a depth per ticket later; this ticket only lets the review follow the size of the diff. Spec: C10, C5 (budget per session), C19 (cost measured).

## Current state

- `src/ariane/review_session.py:90-113`: every reviewer session is built from `[agents.reviewer]` alone (model, tools, `max_budget_usd`, `max_tokens`, `timeout_minutes`), whatever the diff.
- `src/ariane/review.py:208-291`: the prompt is the same for every change; the diff is cut at `MAX_DIFF_CHARS = 200_000` (`review.py:14`), and the rules ask for an adversarial review of the whole change.
- `src/ariane/replay.py:67` and `src/ariane/verify.py:199` compute the diff given to the reviewer; nothing counts its lines.
- `src/ariane/config.py:246-286`: `[agents.<role>]` accepts `runtime`, `model`, `tools`, `max_budget_usd`, `timeout_minutes`, `max_tokens`; the reviewer's model must differ from the implementer's (`config.py:194-198`).

## Decided spec

- New optional table `[agents.reviewer.small]` with a required key `max_lines` (positive integer) and optional `model`, `max_budget_usd`, `max_tokens`, `timeout_minutes`, each replacing the reviewer's value for a small change. The runtime and the tools stay the reviewer's. `small.model` (when given) must differ from `agents.implementer.model`, with the same error wording as today (C10). Any other key is refused, naming it.
- **Small change.** Before each review round (and in `ariane verify`), Ariane counts the changed lines of the reviewed diff (`git diff --numstat <base> <commit>` without `work/`: added plus deleted lines, a binary file counting 0). When `[agents.reviewer.small]` exists and the count is at most `max_lines`, that round's reviewer sessions use the small settings, and the prompt gains: "This change is small (N changed lines). Review the changed files, their tests and the code that calls them; do not survey the rest of the repository."
- Otherwise nothing changes. Without the table, behaviour is exactly today's.
- **Records.** The journal entry `ticket.review.started` says "small change (N changed lines, at most M): small reviewer settings" or "N changed lines"; `metrics.json` already records each session's model and cost and gains `changed_lines` per reviewer session.
- Ariane's own `ariane.toml` and the example files are not given a `small` table here: the owner chooses the values.
- A new ADR (next free number) records the mechanism, why the threshold is on changed lines (measurable, C3's first signal), and why the different-model rule still applies.
