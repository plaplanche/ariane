# Product brief: Stop the fix rounds when a fix session changes nothing, instead of reviewing the same commit again (C10, C19)

- Source: issue #135 (https://github.com/plaplanche/ariane/issues/135)

## Issue

Prefilled from the issue title and body (never its comments).

## Context

C10 allows at most two automatic fix rounds after a `no-go` (or blocking checks red after a round), then hands the ticket to a human. In the benchmark on a reference project, a fix session made no change at all, and Ariane replayed the checks and ran a second full review on the very same commit: same diff, same input, a paid review that could only repeat the first one. Spec: C10 (fix rounds), C19 (cost and rounds measured).

## Current state

- `src/ariane/flow.py:417-448`: `_check_and_deliver` loops over the rounds; after `_fix` it takes `checked = git.head(...)` (`flow.py:422`) and always replays and reviews again, whether the head moved or not.
- `src/ariane/flow.py:332-353`: `_fix` runs the fix session and `_commit_agent_work`.
- `src/ariane/flow.py:355-395`: `_commit_agent_work` stops with "the agent changed no file" only when nothing changed since the ticket's start commit (`flow.py:371-375`, `394-395`), which is never the case in a fix round. `git.commit` returns False when there is nothing to commit (`src/ariane/git.py:311-335`), and that result is only used for the journal.
- An agent may also commit by itself (no tool rule denies `git commit`), so "Ariane committed nothing" and "the head did not move" are not the same.

## Decided spec

- In `_fix`, Ariane takes the head before the fix session and after `_commit_agent_work`. When they are equal, the fix round **made no change**:
  - the journal gets a new entry `ticket.fix.unchanged` ("Fix round N changed nothing"), with the session's summary (it may explain why it disagrees with the findings);
  - no replay and no review run for that round;
  - the rounds stop and the ticket is delivered as when the rounds are exhausted: a draft pull request with the last review (`no-go`) and the last replayed results, status `needs a human`, and the stop line says "fix round N changed nothing" instead of "still no-go after 2 fix rounds".
- A fix session that stopped for budget, turns, timeout or error keeps today's behaviour (`flow.py:389-393`).
- `metrics.json` records the round as run (`rounds`) and a new field `unchanged_fix_rounds` (count); `ariane report` is not changed.
- The simplest option is taken (stop, no second implementer attempt): an ADR amendment to ADR 0027 records it and the rejected alternative (rerunning the fix session once, told that it changed nothing).
