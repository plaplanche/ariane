# Product brief: Commit the journal entries written after the push, and stop calling the branch "pushed" before it is (C1, C11, C23)

## Context

A ticket's folder is its readable state (C1, C23), and the branch is pushed once (C11, ADR 0027). To push once, Ariane commits the records just before the push and writes nothing on the branch afterwards; but it still writes journal entries after the push ("Pushed", "Delivered" with the pull request, the statuses warning). They stay uncommitted in the ticket's working tree: the tree is dirty after every delivery, and the branch's record ends before the pull request exists. The status committed before the push also says "pushed" while nothing is pushed yet. In the benchmark, every delivered ticket left such a dirty tree. Spec: C1 (status file records Ariane's last action, never a state it cannot know), C11, C23.

## Current state

- `src/ariane/delivery.py:59-71`: the status is set to `pushed` / "<branch> pushed; opening the pull request" (or `needs a human` / "<branch> pushed; ...") and committed, then the head is pushed (`delivery.py:73-76`).
- `src/ariane/delivery.py:77-94`: after the push Ariane writes `ticket.pushed`, `ticket.delivered` and, when statuses are refused, `ticket.warning.statuses_refused` (`delivery.py:136-141`) to the journal; the comment at `delivery.py:78` says "Nothing is committed from here on: the pushed commit is the one CI runs on". These entries are never committed.
- `src/ariane/flow.py:496-499`: `_commit_record` commits only `work/<n>/`.

## Decided spec

- **Status before the push.** The status committed before the push says what is true then: `pushing`, "pushing <branch>, then opening the pull request" (`needs a human`, "pushing <branch>, then opening a draft pull request: the review is still no-go" for a draft).
- **After the pull request.** Once the pull request is opened and the statuses published, Ariane sets the status to `delivered`, "pull request #<p> opened: <url>" (or `needs a human`, "draft pull request #<p> opened: <url>"), then commits `work/<n>/` in one commit `#<n>: record the pull request`, on the local branch only. It is not pushed: the branch stays pushed once, CI and the statuses stay on the pushed commit, and the next push of the branch (an `ariane update`) carries this commit. The ticket's working tree is clean afterwards.
- When the pull request is refused after the push, today's stop path already commits the stop record (`flow.py:501-512`); it is unchanged.
- An amendment to ADR 0027 records the choice and the rejected alternative: pushing the records commit as a second push (CI would run again and the statuses would have to move to the new head).

## Release note

Fixed: after a delivery the ticket's working tree is clean and its record, kept on the local branch, ends with the pull request.
